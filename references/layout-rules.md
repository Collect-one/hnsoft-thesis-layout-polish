# 版面美化规则

## 1. 任务边界

版面美化只解决“看起来和翻页是否合理”，不改变论文的事实、结构、角色顺序和学术结论。

上游优先级：

1. 学校格式要求；
2. 论文结构和内容正确性；
3. 图片与表格的可读性；
4. 美观和页数偏好。

如果美化目标与前三项冲突，停止并询问用户。

## 2. 页面空白判定

检查范围从前置部分之后的正文第1页开始，即页脚编号为1的页面；若论文使用其他页码体系，先确认正文起始页。

以A4正文版心计算，一行正文约22磅。

- 非章末页：理想为0行，通常不超过1行，困难情况下不超过2行。
- 章末页：允许大于2行空白，但应尽量避免出现只有一段或一个代码框的页面。
- 空白行按页面最下方有效正文或图表边界到正文下边界计算，不把页脚、页码和页眉算作正文内容。
- 目录、摘要、结论、参考文献和致谢等独立部分的最后一页，可参照章末页处理。

空白处理优先级：

1. 小幅缩小图片；
2. 在同一小节内调整图片、图题和说明文字的位置；
3. 在同一小节内调整图文顺序；
4. 轻微压缩重复、空泛表述；
5. 调整表格拆分位置；
6. 移动代码块。

禁止通过设置超大行距、分布对齐、空白段落或增加无意义文字来“填满”页面。

## 3. 图片规则

- 默认保持宽高比并不裁剪图片内容。
- 用户明确允许时，可小幅放大、缩小或调整显示比例；不得为了填满页面把关键文字缩到无法辨认。
- 图片宽度尽量保持一致；为统一宽度而放大较小图片时，应获得用户允许，并以文字可读为前提。
- 缩放后至少保证：100%页面视图可辨认截图中的主要正文、按钮和关键操作；A4打印后关键信息仍可核对。实际项目截图允许轻微不清晰，但不能模糊到无法确认内容。
- 明显比例变形仅在用户明确接受时保留，并记录为当前论文的“已确认例外”。
- 图片下方紧跟图题；图题不得单独落到下一页。
- 图前应有对应说明文字，“如图X.X所示”位于图前文字末句。
- 不能为了让图片留在当前页而大幅压缩上一页正文。

## 4. 表格规则

### 先按当前分页判断

每次只判断当前最早出现问题的表。添加续表题或移动表格后，必须重新分页，不能沿用之前的分页结论。

### 整表优先

如果表格较小，且整表移至下一页后，前一页只剩不超过2行的空白，优先保持整表完整。

### 必须拆表时

- 在下一页从实际行边界开始续表；
- 页首增加右对齐的“续表X.X 表题”；
- 重复表头；
- 保持三线表：顶线、表头线、底线和必要的表内行结构；
- 续表题与表头不得分离；
- 不要复制整张表后再留下重复空行。

### 表格列宽

- 优先保证第一列等短文本不出现单独一个汉字被挤到下一行；
- 调整列宽前先保持总宽度约16厘米；
- 不通过缩小表内字体来强行挤出空白。

## 5. 代码框规则

### 识别

只对“核心代码如下所示”等明确说明的核心代码区域建立或调整代码框。

不把以下内容视为需要代码框的核心代码：

- 正文中的函数名、接口名、变量名；
- 参考文献中的 DOI、URL；
- 图表题注中的英文；
- 普通命令词或短行内代码。

### 框体

- 核心代码块应使用连续、完整的单线框；
- 所有代码行共享一个框体，不要每行一个独立小框；
- 中文使用宋体五号，其他字符使用 Times New Roman 五号；
- 代码框不能跨页；
- 代码框前有“核心代码如下所示”或同等引导语；
- 代码内容可以是精简摘录，但必须与本小节功能对应；关键省略可用短注释说明。

### 没有代码框时

在用户明确授权后补框：

1. 识别完整代码块范围；
2. 保留原有字体、字号、缩进和行距；
3. 添加连续的四边单线框；
4. 框体不跨页；
5. 用 PDF 目检，确认边框连续且没有把标题、图题、正文段落套进框内。

## 6. 图文顺序

- 文字说明在上。
- 图片在中。
- 图题在下。
- “如图X.X所示”是图前说明文字的末句。
- “如表X.X所示”是表前说明文字的末句。

不要为了消除空白把图题放到图片上方，也不要把图题并入正文。

## 7. 章节结构与角色顺序

版面美化不判断结构。

- 不自行改变章节顺序。
- 不自行改角色顺序。
- 不自行把角色型第4章改成功能型，反之亦然。
- 如果版面调整需要改变结构或角色顺序，停止；若已安装 `hnsoft-thesis-format-review`，交给该 Skill，否则向用户说明结构判断无法完成并请求确认。
- 角色顺序的权威来源是该论文的总体功能模块图，不是固定角色清单。
- 角色型第4章的三级功能标题按项目实际角色功能编写，不要求与总体功能模块图逐项对应；不同角色可以出现同名功能，不得因重名而合并、删除或互调这些小节。
- 同一论文存在多个副本时，只按用户确认的唯一准稿判断版面；不得把旧版截图或旧版 PDF 的分页与唯一准稿混用。

## 8. 章末页

章末页允许留白，但应检查是否出现：

- 只有一行正文；
- 只有一张图题；
- 只有代码框；
- 只有表格末行。

如果出现，优先把前一页的最后一个完整块调整到本章前面，或把该块与上一页的说明合并；但不能因此删除实质内容或改动章节结构。若无法在不损害可读性的前提下改善，保留章末空白是允许的。用户明确接受“章末仅有一个代码框”或类似情况时，记录为“已确认例外”。

## 9. 最终验收

- [ ] 非章末页页尾空白0～2行。
- [ ] 章末页没有孤立标题、孤立图题或不合理空页；用户明确接受的孤立代码框等例外已记录。
- [ ] 所有图题在图片下方，图前说明在上。
- [ ] 所有图前/表前引用是上一段文字末句。
- [ ] 所有跨页表有续表题和重复表头。
- [ ] 所有核心代码框连续且不跨页。
- [ ] 图片没有未经用户确认的明显变形，关键文字可读。
- [ ] 目录已更新，PDF页码与正文一致。
- [ ] 若已安装格式与结构审查 Skill，用它复审；若未安装，明确标注“格式复审未执行”。
- [ ] 用户已确认的本论文例外已记录，未错误推广为通用规则。
